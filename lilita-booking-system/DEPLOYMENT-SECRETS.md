## Generate Before Deployment

### JWT_SECRET (Generate Now)
This is used to sign authentication tokens.

**Generate a secure 32+ character string:**
```bash
# Option 1: Use OpenSSL
openssl rand -base64 32

# Option 2: Use Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# Example output:
# CxI8vKp9mL2qR4wT6nJ7hF0sB3dE5uG8X9yZ2aB4c=

# Copy this value → Paste into Railway JWT_SECRET variable
```

### Database Password (Generated by Railway)
Railway creates this automatically when PostgreSQL is added.

**Where to find it:**
1. Railway dashboard → PostgreSQL service
2. Click "Variables" tab
3. Look for `POSTGRES_PASSWORD`
4. This is auto-generated - don't change it

## Backup & Recovery

### If Database Password is Lost
1. Go to Railway PostgreSQL service
2. Click "Reset Password" button
3. Save new password securely
4. Update Railway variables
5. Redeploy backend

### If JWT_SECRET is Compromised
1. Generate new JWT_SECRET
2. Update Railway variables
3. Redeploy backend
4. All existing tokens become invalid (users must re-login)

### If Repo is Accidentally Exposed
1. Immediately rotate all secrets
2. Check git history for exposed credentials
3. Use `git filter-branch` to remove secrets from history
4. Force-push to reset history
5. Notify all users to change passwords
